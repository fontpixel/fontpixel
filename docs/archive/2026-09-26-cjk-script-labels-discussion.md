# 讨论：中日韩文字集合图口径与首页"书写系统·完整"判定的统一

- 日期：2026-09-26
- 参与者：Tom Chen（维护者）、Claude（Opus 5.5）
- 状态：**已归档**。现行规则见 [specs/cjk-script-labels.md](../specs/cjk-script-labels.md)。
- 目的：保留评审前的讨论记录。下文是评审时的原稿，其中的推荐（方案 C）**没有被采用**。

> **最终决定（评审之后）**
>
> - Codex 评审建议采用方案 C，核心层取 99%，标签改为"较完整/部分"。
> - 维护者最终选择**方案 B**：简体看通用规范一级字，繁体看常用国字甲表，韩文看 KS X 1001 谚文，
>   都是 ≥ 98%；日文要求 JIS 平假名 83、片假名 86 及 ー・ 全部覆盖，且第一水準 ≥ 98%。
>   "不完整"的下限为 10%；日文"不完整"要求平假名、片假名各 ≥ 95% 且第一水準 ≥ 10%。标签文字不变。
> - 集合图：假名主数改为 JIS 平/片假名加 ー・ 共 171 个（不是下文的 178 个）；
>   基本注音符号为 37 个注音字母，并**计入**合并总数，合并总数为 26,281。一度把 5 个声调符号也并入了基本注音，

> - Codex 指出下文 §7 有两处不准确：索引里的比例经过舍入，不同字表的最大值也可能来自不同字号，
>   所以"繁体覆盖字数的估算是准确的"不成立；另外 `cjkCoverageSignature` 不会刷新首页的
>   `scripts`，必须提高 `PIPELINE_VERSION`。实现时已提高到 23。

## 1. 问题

维护者提出了两个问题：

1. 中日韩文字集合图里，中国大陆、台湾、日本、韩国的汉字各自采用什么标准？
2. 首页"书写系统"筛选中的"完整"是怎么定义的？它和集合图有什么出入？怎样统一比较好？

## 2. 现状（改动前）

### 2.1 中日韩文字集合图

代码：`pipeline/opf/coverage/cjk.py` 中的 `cjk_sets()`；展示：`site/src/components/CjkCoverage.astro`；文案：`site/src/i18n/cjk.ts`。

| 圈 / 面板 | 采用的字集 | 字数 |
|---|---|---|
| 台湾（`tw`） | 《常用国字标准字体表》（甲表）＋《次常用国字标准字体表》（乙表） | 4808 + 6343 = **11151** |
| 中国大陆（`sc`） | 《通用规范汉字表》（2013），一、二、三级合计 | 3500 + 3000 + 1605 = **8105** |
| 日本（`jp`） | JIS X 0208 第一水準漢字 | **2965** |
| 韩国（`kr`） | KS X 1001 汉字 ∩ CJK 统一表意文字 | **4620**（另有兼容汉字 268 个，单列） |
| 日文假名（`kana`） | 平假名 + 片假名 + 附加符号 + 扩展区块 + 半角假名 | **579**（86 + 90 + 13 + 327 + 63） |
| 谚文音节（`hangul`） | U+AC00–D7A3 | **11172**（其下小字列出 KS X 1001 常用 2350 个和谚文字母） |
| 注音符号（`bopomofo`） | U+3105–312F，U+31A0–31BF | **75** |
| 合并去重（`combined`） | 四张汉字表 ∪ 假名 579 ∪ 谚文音节 ∪ 注音 | **26727** |

集合图显示的是覆盖数和百分比，"完整"表示缺字为 0，即 100%。

说明：
- 台湾圈的标签是"台湾 · 常用繁体字"，但字集实际包含了次常用字，标签和内容不符。
- 通用规范一、二、三级和台湾甲、乙表的分层数据（`sc-l1/l2/l3`、`tw-common`、`tw-less`）在 `cjk_sets()` 里已经算出来了，但集合图上没有显示。

### 2.2 首页"书写系统"筛选

代码：`pipeline/opf/coverage/engine.py:110-170`（`SCRIPT_REFERENCE_CHARSETS`、`detect_scripts`）。`site/src/lib/rating.ts:34-43` 手动复制了同一套定义。文案在各语言的 `scriptRules` 中。

- 分数 ≥ **90%** 算"完整"；10%–90% 算"（不完整）"。
- 同一族内取各字号中最好的一档（`build.py: merge_scripts`）。

| 书写系统 | 判定字集 |
|---|---|
| 简体中文 | max(GB 2312 6763 字，通用规范 8105 字) |
| 繁体中文 | Big5 常用字面 A440–C67E，共 **5401** 字 |
| 日文 | 平假名、片假名各 ≥ 95% 作为前提，再看 JIS X 0208 第一水準 |
| 韩文 | max(KS X 1001 谚文 2350，现代谚文全表 11172) |

### 2.3 同一数据上的第三套阈值：徽章

`engine.py: _BADGES`：GB 2312、通用规范、Big5 常用、常用国字 4808、JIS 第一水準、KS X 1001 谚文等，≥ **99%** 时颁发徽章。

也就是说，现在同一批数据上有三种阈值：集合图 100%、徽章 99%、书写系统 90%。

## 3. 发现的出入

1. **繁体用的字表不同。** 首页用 Big5 常用 5401 字，集合图用 4808 + 6343 共 11151 字。Big5 常用 ≈ 甲表 4808 − 1 + 另外 594 个字（主要是异体字和日韩用字）。所以首页上"繁体完整"的字体，在集合图台湾圈里可能只有 60–70%。
2. **繁体有误判。** 日文 JIS 字体的汉字和 Big5 常用字大量重叠，于是被标成了"繁体中文"完整。例如 jiskan、k12、k14、izumi 的 Big5 常用覆盖率约 92.6%，但甲表只有 93.9%，缺约 290 个台湾常用字；韩文 dos-gothic 系列同理。
3. **简体口径不一。** 首页取 GB 2312 和 8105 的较高者，集合图只看 8105。GB 2312 里有 125 个字不在 8105 内。cubic-11、hexin-pixel 覆盖了全部一级字，但 GB 2312 二级的生僻字不够，被判为"简体（不完整）"。
4. **"韩国"指的内容不同。** 首页韩文看谚文，集合图的韩国圈看汉字。两种做法都有道理，但读者容易以为是同一个标准。
5. **假名范围不同。** 首页只看平/片假名 176 个；集合图的假名总数是 579，其中大量是变体假名等历史字符和半角假名。
6. **阈值不一，而且"完整"一词有误导。** 书写系统的"完整"只要求 90%，GB 2312 最多可以缺 676 个字，但标签"简体中文"和"简体中文（不完整）"并列，读者会以为前者是 100%。
7. **定义重复。** `rating.ts` 手工复制了 `engine.py` 的定义，改一处容易漏改另一处。

## 4. 讨论过程

### 4.1 第一轮：Claude 的初始建议（方案 B）

原则："书写系统完整"回答的是"能不能正常书写这门语言"，用各地区的核心常用层，阈值定高一些。"是否符合 GB 2312 / Big5 / 8105 全表"这类标准合规问题交给覆盖率筛选和徽章。`engine.py` 的注释本来就是这样区分的："能否书写"和"是否达到某个标准"。

| 书写系统 | 完整的判定 |
|---|---|
| 简体 | 通用规范一级 3500 ≥ 98% |
| 繁体 | 常用国字甲表 4808 ≥ 98% |
| 日文 | JIS X 0208 的平假名 83 个、片假名 86 个，以及 ー・，全部覆盖，且 JIS 第一水準 ≥ 98% |
| 韩文 | KS X 1001 谚文 2350 ≥ 98% |

| 书写系统 | 不完整的判定 |
|---|---|
| 简体 | 通用规范一级 3500 字，覆盖率 **≥10% 且 <98%** |
| 繁体 | 常用国字甲表 4808 字，覆盖率 **≥10% 且 <98%** |
| 日文 | JIS 基本平假名 83 个、片假名 86 个，**各覆盖 ≥95%**，但**未满足日文完整条件** |
| 韩文 | KS X 1001 谚文 2350 个，覆盖率 **≥10% 且 <98%** |


理由：
- 这几张表在集合图里都有对应（`sc-l1`、`tw-common`、`jp`），首页的"完整"能在图上找到依据。
- 核心表小，90% 就意味着缺几百个常用字，所以阈值要提高到 98%。
- GB 2312 包含一级字 3500 个中的 3498 个，原来靠 GB 2312 过关的字体基本不受影响。
- 能修掉 §3 第 2 点的 JIS 字体误判。

### 4.2 第二轮：维护者的方案（方案 A）

> 简体、繁体都用通用规范汉字表（8105）和常用与次常用国字合计（11151），集合图不变，把"完整"改为全表的 90%，也可以讨论其他阈值，比如 85%。日文、韩文不变。

Claude 模拟后的结果如下（数据方法见 §7）：

| 阈值 | 简体完整 | 繁体完整 |
|---|---|---|
| 现状 | 36 | 40 |
| 全表 ≥ 90% | 21 | **14** |
| 全表 ≥ 85% | 30 | 15 |
| 全表 ≥ 80% | 37 | 15 |

Claude 不赞成方案 A，理由如下：
- **繁体找不到合适的阈值。** 目录里的繁体像素字体呈两极分布。多数字体甲表全有，乙表覆盖 40–60%，合计落在 66–80%；剩下的是 92% 以上的 Unifont、文泉驿这类大字库。中间是空的，所以阈值从 80% 调到 90%，结果都只剩 14–15 个。chang-ban-dian-song、zlabs-pixel-12px、poxiao-pixel、muzai-pixel 这些同时覆盖了甲表全部和 8105 全部的字体，也会被判为"繁体（不完整）"。
- **简繁难度不对等。** 简体全表 90% 是 7295 字，相当于一二级全有再加一半三级字。繁体 90% 是 10036 字，要求乙表覆盖约 84%，而乙表里罕用字很多。同一个百分比，对繁体苛刻得多。
- **GB 2312 全覆盖的字体会丢掉"简体完整"。** isas-song、isas-fangsong、chusung、fonsung、lyusung、clfn、uranus-pixel 在 8105 里只覆盖约 82%（6638 字）。
- 如果坚持用全表，简体可以取 80%（8105 × 0.8 ≈ 6484 字，约等于一二级 6500 字）。繁体则需要约 60% 才能接纳"甲表全有加一半乙表"的主流字体，这时"90%"的说法已经没有意义。

### 4.3 第三轮：维护者否定方案 B

> 通用规范一级、常用国字甲表太少，不够用，用的时候缺字很厉害，我希望保证覆盖量。

Claude 接受这一点。一级 3500 字和甲表 4808 字虽然能覆盖绝大多数日常文本，但人名、地名、专名缺字明显，不足以代表"够用"。

### 4.4 第四轮：Claude 的修订方案（方案 C，当前推荐）

用两个条件把"覆盖量"和"常用字齐全"分开卡：

| | 条件一：覆盖量 | 条件二：核心层兜底 |
|---|---|---|
| 简体完整 | 通用规范汉字表 8105 中覆盖 **≥ 6,500 字** | 一级字 ≥ 98% |
| 繁体完整 | 常用与次常用国字 11151 中覆盖 **≥ 6,500 字** | 甲表常用字 ≥ 98% |
| （不完整） | 全表覆盖率 ≥ 10%，但未达到"完整" | — |

理由：
- **字数门槛相同。** 6,500 是通用规范一、二级合计的字数，也和 GB 2312（6763）同一量级，符合维护者"保证覆盖量"的要求。换算成百分比，简体约 80.2%，繁体约 58.3%。直接给同一个百分比做不到简繁对等，因为两张全表里罕用字的比例不同。
- **核心层兜底防止拼凑出来的覆盖量。** 只看总数的话，JIS 字体能凑够 6,500 字（例如 jiskan 在繁体全表里覆盖 7,255 字），却缺台湾常用字约 290 个。条件二专门拦这种情况。
- **集合图不需要改结构。** 两个条件用的字集都已经在图里（全表圈和分层数据）。只要在大陆圈和台湾圈里加一行小字，例如"一级字 3,500/3,500"、"常用字 4,808/4,808"，首页的判定就能在图上找到依据。
- **文案好写。** 例如"通用规范汉字表覆盖 ≥ 6,500 字，且一级字 ≥ 98%"。直接写字数，比写一个百分比更直观。
- 日文、韩文的判定按维护者的意见保持不变。

模拟结果：

| | 现状 | 方案 C（核心 ≥ 98%） | 变化 |
|---|---|---|---|
| 简体完整 | 36 | 36 | 增加 hexin-pixel（6,989 字，一级全有）；减少 ark-pixel（一级 95.9%） |
| 繁体完整 | 40 | 31 | 减少 jiskan、k12、k14、izumi、dos-gothic、dos-myungjo、dos-saemmul（甲表不全，属于原先的误判）；减少 fashionbitmap16（甲表全有，但总共只有约 6,191 字）；减少 ark-pixel（甲表 90.9%） |

如果核心层改为 ≥ 99%：简体 34 个（mona、mona-s 的一级字为 98.5%，会被排除），繁体 29 个。

关于 ark-pixel 的更正：Claude 在对话中曾推测"ark-pixel 的大字号应该能过"。复核后发现，index.json 里的族级覆盖率本来就是**各字号中的最大值**。ark-pixel 覆盖最好的字号，一级字也只有 95.9%，甲表只有 90.9%，所以按方案 C 会真实地降为"不完整"。原先的推测不成立。

### 4.5 未采用的方向：按字频加权的"文本覆盖率"

"用的时候缺不缺字"最直接的衡量方式，是按真实语料的字频加权，算出字体能覆盖多少比例的文本。这种方法没有列为方案，原因是：需要引入可授权的简繁字频语料，结果不容易对应到集合图上的某张字表，文案也难写。可以作为以后的方向。

## 5. 集合图本身的改动（维护者提出，Claude 均同意）

### 5.1 假名

- **维护者：** 假名 579 个里有不少很少用的字，比如半角假名。改为：平/片假名用大字加进度条，其他假名用小字、不带进度条。
- **Claude：** 同意。主显示的平/片假名 176 个（86 + 90）也和首页日文的判定口径一致。补充建议：附加符号里的长音符 **ー** 和中点 **・** 在日文里天天用，建议并入主数（共 178 个）。其余附加符号（゙ ゚ ゛ ゜ ゝ ゞ ゟ ゠ ヽ ヾ ヿ）、扩展 327 个、半角 63 个，都用小字、不带进度条。

### 5.2 注音符号

- **维护者：** 注音里也有不少罕用字，要不要干脆不写在集合图里？
- **Claude：** 建议保留，但缩小范围。注音是台湾的书写系统，台湾字体有没有注音，确实有人关心（例如 taipei-pixel）。现在统计的 75 个码位里，只有 U+3105–3129 这 **37 个是基本符号**，其余是方言用字（ㄪㄫㄬ 等）和闽南语、客家语扩展（U+31A0–31BF）。建议主数改为 37 个，其余用小字、不带进度条；**注音不计入合并总数**。另外可以考虑把声调符号 ˉˊˇˋ˙（位于 Spacing Modifier Letters 区）并入主数，目前没有统计。

### 5.3 "所选中日韩字集合并，去除重复"

- **维护者：** 合并统计的是台湾 · 常用繁体字、中国大陆 · 通用简体字、日本 · JIS X 0208 第一水準、韩国 · KS X 1001 统一汉字、平/片假名、谚文音节，合起来去重？
- **Claude：** 同意。新的合并口径是 tw ∪ sc ∪ jp ∪ kr ∪ 平/片假名 ∪ 谚文音节 11172，总数从 26727 变为 **26249**（按平/片假名 176 个计算；若并入 ー・ 则为 26251）。需要注意：谚文音节用 11172 个全表，和汉字用全表的思路一致，但它占合并总数的约 43%，只收 KS X 1001 常用 2350 个音节的韩文字体，合并百分比会偏低。这是现在就有的情况，不是这次改动带来的。

### 5.4 标签更名

"台湾 · 常用繁体字"改为"**台湾 · 常用与次常用国字**"，让标签和字集一致。其他 4 种语言的文案同步修改。

## 7. 数据方法与局限

- 字集数据：`pipeline/opf/coverage/data/**` 中的字表，由 `opf.coverage.charsets.load_charsets()` 载入。Unicode 版本为 17。
- 字体覆盖率：来自当前构建产物 `site/public/data/index.json`，共 461 个族。其中 `coverage[]` 是**族内各字号对每张字表覆盖率的最大值**。
- 局限：模拟时把不同字表的最大值组合在一起用。方案 C 的两个条件，理论上可能由不同字号分别满足，而正式实现会逐个字号判定，再取最好的一档。因此模拟结果是**上限**，实际通过数可能略少，但目前没有发现两个条件由不同字号分别满足的族。
- 繁体覆盖字数的估算方法：甲表覆盖率 × 4808 + 乙表覆盖率 × 6343。两张表不重叠，所以这个估算是准确的。
