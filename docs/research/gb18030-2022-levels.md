# GB 18030-2022 三个实现级别（Implementation Level 1/2/3）精确定义与构造规则

调研时间：2026-08-21。核心依据：GB 18030-2022 起草单位「中国电子技术标准化研究院（CESI）」官方发布的
《国家标准 GB 18030-2022〈信息技术 中文编码字符集〉理解与使用》（下称《理解与使用》），其中逐条引用了标准正文
（标注为【标准条文】的方框内文字＝GB 18030-2022 原文），可视为除购买标准正文全文外可获得的最权威二手来源。
另有 Unicode 技术委员会文件（Peter Constable, L2/22-274）与多篇独立中文技术文章交叉印证，结论一致，**未发现实质性冲突**。

---

## 0. 一句话结论

- **级别1** = 单字节全部 ∪ 双字节全部 ∪ 四字节中「CJK统一汉字」落在 BMP 但未被双字节收录的 66 个字符（U+9FA6..U+9FEF，排除 U+9FB4..U+9FBB）∪ CJK统一汉字扩充A（U+3400..U+4DBF，6582字）—— 本质上＝GB/T 13000（≡Unicode/ISO 10646）**基本多文种平面（BMP）中本标准收录的全部汉字**，共 **28575** 字符（汉字及部首 27584 个）。
- **级别2** = 级别1 ∪ 《通用规范汉字表》8105字中不属于级别1的 **196** 个汉字（3个二级字+193个三级字，均位于辅助平面SMP，落在CJK统一汉字扩充B~F区段），共 **28771** 字符（汉字及部首 27780 个）。
- **级别3** = 级别2 ∪ 标准收录的全部剩余 CJK 统一汉字及其扩充A–F ∪ 214个康熙部首（U+2F00..U+2FD5），共 **89106** 字符（汉字及部首 88115 个，其中汉字 87887 个）。
- 三级为**严格包含关系**：级别1 ⊂ 级别2 ⊂ 级别3（标准原文明确写出"实现级别2包含实现级别1""实现级别3包含实现级别2"）。

## 1. 标准原文（标准条文，逐字引用）

来源：《理解与使用》第 22–23 页，2.9 节"三个实现级别的界定"，方框内为【标准条文】原文引用（即 GB 18030-2022 正文第9章）：

> **9 实现的级别**
>
> **9.1 通则**
> 本文件规定三个实现级别。符合相应实现级别的系统软件产品，应提供相应实现级别范围内全部字符的输入输出功能。
>
> **9.2 实现级别1**
> 实现级别1支持本文件的单字节编码部分、双字节编码部分和四字节编码部分的CJK统一汉字（即0x82358F33—0x82359636）和CJK统一汉字扩充A（即0x8139EE39—0x82358738）。
> 任何本文件适用的产品均应满足实现级别1的要求。
> 注：根据软件应用需要，实现级别1还可选择支持表3列出的任何一种或多种非汉字文种。
>
> **9.3 实现级别2**
> 实现级别2包含实现级别1。此外，实现级别2还支持《通用规范汉字表》中的没有包含在实现级别1之内的编码汉字。《通用规范汉字表》所收汉字在本文件中的代码位置和字形，见附录E。
> 系统软件及支撑软件，应满足实现级别2的要求。
> 注：系统软件及支撑软件包括但不限于操作系统、数据库管理系统、中间件（软件产品分类的信息见GB/T 36475）。
>
> **9.4 实现级别3**
> 实现级别3包含实现级别2。此外，实现级别3还支持本文件规定的全部汉字及表3中的康熙部首。
> 用于政务服务和公共服务的产品应满足实现级别3的要求。
> 注：政务服务和公共服务行业包括但不限于铁路运输业、道路运输业、水上运输业、航空运输业、多式联运和运输代理业、邮政业、货币金融服务业、保险业、土地管理业、卫生、国家机构、社会保障等（行业分类的信息见GB/T 4754）。

同文件第 12–13 页，2.4 节"标准收录的字汇"中【标准条文】4.4（用于精确定位"66个CJK统一汉字"的 Unicode 范围）：

> **4.4 四字节部分**
> 四字节的部分收录了上述双字节字符之外的GB/T 13000 的 **66 个 CJK 统一汉字（9FA6 到 9FEF，不包括 9FB4 到 9FBB 的 8 个字符）**、CJK 统一汉字扩充A、CJK 统一汉字扩充B、CJK 统一汉字扩充C、CJK 统一汉字扩充D、CJK 统一汉字扩充E、CJK 统一汉字扩充F和已经在GB/T 13000中编码的少数民族文字的字符。四字节部分的字符按照附录C的规定。

> 关键事实：GB/T 13000《信息技术 通用多八位编码字符集（UCS）》"等同采用（idt）"国际标准 ISO/IEC 10646，其编码结构、收录字符与 ISO/IEC 10646（即 Unicode）保持一致（《理解与使用》第 33–34 页，4.1.5节）。因此 **GB/T 13000 代码位置＝Unicode 码位（U+）**，可直接互换记号。

## 2. 条文解读中的精确字符数（同文件 2.9.1–2.9.3 节，第23页）

> **2.9.1 实现级别1**
> 实现级别1是对具备中文信息处理功能的产品的基本要求，共包含 **28575** 个字符，其中汉字和汉字部首数为 **27584** 个。字汇基本等同于本标准上一版，即 GB 18030—2005 前言部分的强制性要求，但在此基础上增加了66字……本标准实现级别1规定的汉字与GB/T 13000的BMP中的汉字一一对应。换言之，凡采用GB/T 13000内核的产品，只要支持BMP，即支持本标准实现级别1。
>
> **2.9.2 实现级别2**
> 实现级别2在字汇上相较实现级别1增加了 **196** 个汉字，总字符数为 **28771** 个，其中汉字和汉字部首数为 **27780** 个。该级别的要义在于满足实现《通用规范汉字表》的要求。《通用规范汉字表》……共收录8105个汉字，该表于2013年由国务院批准发布。对于采用GB/T 13000内核的产品，完整支持《通用规范汉字表》的汉字，在技术上有较高要求，因为该表规定的196个汉字（**3个二级汉字和193个三级汉字**）位于GB/T 13000的 **SMP（辅助多文种平面）** 中。
>
> **2.9.3 实现级别3**
> 实现级别3包括标准内定义的全部 **88115** 个汉字和汉字部首，以及单字节编码部分和双字节1区、5区的各类图形符号，总计 **89106** 个字符。

补充计数依据（同文件第17页，2.7.1节"CJK统一汉字"）：

| 区块 | 字符数 | Unicode区间（官方Blocks.txt，见§5） |
|---|---|---|
| CJK 统一汉字（主区块） | 20976 | U+4E00–U+9FFF |
| CJK 统一汉字扩充A | 6582 | U+3400–U+4DBF |
| CJK 统一汉字扩充B | 42711 | U+20000–U+2A6DF |
| CJK 统一汉字扩充C | 4149 | U+2A700–U+2B73F |
| CJK 统一汉字扩充D | 222 | U+2B740–U+2B81F |
| CJK 统一汉字扩充E | 5762 | U+2B820–U+2CEAF |
| CJK 统一汉字扩充F | 7473 | U+2CEB0–U+2EBEF |
| **合计** | **87875** | — |

87875 + 12个CJK兼容汉字（U+F900–U+FAFF区块内） = **87887 个汉字**（多篇独立来源反复印证的总量，见§4）。
87887 + 228个汉字部首（214个康熙部首 U+2F00–U+2FD5 + 14个补充CJK部首，属Unicode「CJK Radicals Supplement」U+2E80–U+2EFF区块116个中的14个） = **88115**，与"实现级别3含88115个汉字和汉字部首"完全吻合。
88115 + 991个非汉字图形符号（单字节部分 + 双字节1区、5区，此数目在三个级别中恒定不变：28575−27584 ＝ 28771−27780 ＝ 89106−88115 ＝ 991）＝ **89106**（级别3总字符数），内部数据自洽。

## 3. 可机器执行的构造规则

记号：`U+XXXX..U+YYYY` 表示闭区间（含两端）；`∖` 表示排除；GB18030 内部四字节码位用 `0xAABBCCDD` 表示（与 Unicode 码位为算法/查表双射关系，非直接数值相等）。

### 级别1

```
级别1
  = 单字节部分（GB/T 11383-1989, 0x00..0x7F, 97字符)
  ∪ 双字节部分（GB/T 2312全部图形字符 + GB/T13000 BMP中CJK统一汉字主区块被双字节收录的部分
                + 拉丁/希腊/斯拉夫字母、日文假名、注音符号、汉语拼音、CJK兼容汉字、
                  14个补充CJK部首等, 共21882字符)
  ∪ { U+9FA6..U+9FEF ∖ U+9FB4..U+9FBB }         # GB18030内部码位 0x82358F33..0x82359636；66字符
  ∪ { U+3400..U+4DBF }                            # CJK统一汉字扩充A全部；GB18030内部码位 0x8139EE39..0x82358738；6582字符
  [可选，非强制] ∪ 表3列出的任一/多个非汉字文种（少数民族文字，如蒙古文、藏文、维哈柯文等）

总计：28575 字符（汉字/部首 27584）
等价表述：本标准在 Unicode 基本多文种平面（BMP, U+0000..U+FFFF）内收录的全部汉字 + 非汉字符号（少数民族文字除外，为可选)
```

### 级别2

```
级别2
  = 级别1
  ∪ { 《通用规范汉字表》8105字中不在级别1内的196个汉字 }   # 3个二级字 + 193个三级字；均属Unicode辅助多文种平面(SMP)，
                                                              # 落在CJK统一汉字扩充B..F区段；代码位置见标准附录E

总计：28771 字符（汉字/部首 27780）＝ 级别1 + 196
```

### 级别3

```
级别3
  = 级别2
  ∪ { 标准收录的全部CJK统一汉字（U+4E00..U+9FFF）及扩充A..F（U+3400..U+4DBF, U+20000..U+2A6DF,
       U+2A700..U+2B73F, U+2B740..U+2B81F, U+2B820..U+2CEAF, U+2CEB0..U+2EBEF）中尚未被级别1/2覆盖的全部剩余汉字 }
  ∪ { 12个CJK兼容汉字, 位于U+F900..U+FAFF区块内 }
  ∪ { 214个康熙部首, U+2F00..U+2FD5（表3所列） }

总计：89106 字符（汉字/部首 88115 = 87887汉字 + 228部首）
```

### 包含关系

标准原文明确声明（9.3、9.4条）：**级别1 ⊂ 级别2 ⊂ 级别3**（严格包含，逐级累加，非并列或交叉关系）。

## 4. 交叉印证来源（独立信息源，结论一致）

1. **Unicode Technical Committee 文件 L2/22-274**《Disruptive Changes in GB 18030-2022》，Peter Constable，2022-10-28（Unicode 联盟官方技术文件，英文，独立于中文来源）：
   > "The new edition defines three different levels of conformance requirement ('implementation levels')... • **Level 1** applies to all products with requirements that include support for the URO block (CJK Unified Ideographs) and for CJK Extension A. • **Level 2** applies to 'system software and support software… includ[ing] operating system, database management system and middleware'. [Level 2] adds a requirement to support all characters in the 'Standard Chinese Characters List' (detailed in Annex E); that list has 8105 characters, most of which are in the URO, but also includes some characters from CJK Extensions A through F. • **Level 3** applies to all products 'for government affairs services and public services', and adds the requirement to support all CJK ideographs up through Extension F, as well as Kangxi radicals."
   - 与中文标准原文完全一致（URO = CJK统一汉字主区块 U+4E00–U+9FFF 的业内简称）。
   - 网址：https://www.unicode.org/L2/L2022/22274-disruptive-changes.pdf

2. **英文维基百科 "GB 18030"**：
   > "all products using this standard should implement Implementation Level 1" that includes "66 new BMP characters in the 4-byte encoding region that were added between Unicode 3.1 and Unicode 11.0." "Implementation Level 2 requires the support of List of Commonly Used Standard Chinese Characters[即《通用规范汉字表》], and Implementation Level 3 requires all other specified regions in the standard."
   - "66个新增BMP字符，Unicode 3.1至11.0之间新增"与标准原文"9FA6到9FEF，不包括9FB4到9FBB的8个字符"（74−8=66）精确吻合。
   - 网址：https://en.wikipedia.org/wiki/GB_18030

3. **知乎/搜狐等中文技术文章检索摘要**（WebSearch 聚合结果）：确认"级别1含27584个汉字；级别2在级别1基础上增加196个；级别3含全部87887个汉字和214个康熙部首"，与本文件数字完全一致。
   - https://zhuanlan.zhihu.com/p/618558391
   - https://www.sohu.com/a/705021959_121687423

4. **DICOM Correction Proposal CP-2354**（医学影像行业标准修订提案，2024）：确认 GB18030-2022 "aligns with Unicode version 11.0 on CJK Unified Ideographs and its extensions"，"deletes or changes 51 characters and adds over 10,000"——背景信息与本文一致，但**该文件中的"implementation level"是DICOM/ISO 2022自身的编码级别概念，与GB18030-2022的"实现级别"是两套不同概念，容易混淆，本报告不采用该文件中的"level"数据**。

## 5. 未解决的细节 / 局限性说明

- "表3"（9.2、9.4条注释中提及的列表，列出可选非汉字文种及康熙部首所在分类）的完整表格内容未能在检索范围内获取原始表格（该表应位于标准正文第7章"码位分配"附近，《理解与使用》未完整复制此表格图片，仅引用条文文字）。但其作用边界已可从条文本身精确推断：① 对级别1，表3所列"非汉字文种"（即蒙古文、藏文、维哈柯文、朝鲜文、彝文、傣文等少数民族文字）为**可选**，不构成级别1强制范围；② 对级别3，表3所列"康熙部首"（214个，U+2F00–U+2FD5）为**强制新增项**。此推断不影响本文对三级"汉字覆盖范围"这一核心问题的回答，仅表3的其余罗列细节（各非汉字文种条目全貌）未能逐条核实。
- GB18030内部四字节16进制码位（如 `0x82358F33—0x82359636`）与Unicode码位的对应关系，本文通过标准条文4.4（明确给出Unicode等价区间 "9FA6到9FEF，不包括9FB4到9FBB"）间接验证，两处条文互相印证、结果一致，可信度高；但未逐一实机验证GB18030四字节算法映射的每个码位。
- 未发现不同来源之间存在实质性数值或范围冲突；各独立来源（官方解读文档、Unicode联盟文件、维基百科、多篇中文技术文章）在级别定义、字符总数上完全一致，因此本文未列"冲突对比表"。
